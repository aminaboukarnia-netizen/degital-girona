# NashrClip AI — المرحلة الأولى

هذا المشروع نسخة بداية حقيقية **من دون توليد فيديوهات أو نشر اجتماعي**. الهدف الآن: نشر تطبيق Next.js عربي، تفعيل `/api/health`، وتقديم `/mcp` للقراءة فقط، قبل إضافة المفاتيح أو أي تكلفة.

## الموجود فعلياً في الكود
- صفحة عربية تشرح حالة المشروع بصدق.
- `GET /api/health` يعيد JSON يظهر نجاح تشغيل الهيكل **فقط**، مع بيان أن Turso/Kie والنشر لم تُفعّل.
- `/mcp` بخادوم Streamable HTTP عبر حزمة `mcp-handler` 2 الحديثة، فيه أداتان آمنتان فقط: `project_status` و `workflow_preview`.
- لا مفاتيح API ولا كلمات مرور في الملفات، ولا كود قد ينشر محتوى أو يستهلك رصيدًا.
- إطار Next.js + TypeScript + Tailwind للربط مع Vercel.

## طريقة الرفع إلى GitHub من المتصفح
1. فكّ ضغط ملف ZIP على جهازك، وادخل لمجلد `NashrClip_AI_fase1`.
2. افتح المستودع الحالي في GitHub: `https://github.com/aminaboukarnia-netizen/degital-girona` (الاسم المكتوب في التقرير حرفيًا، ولو فيه خطأ إملائي يمكن إعادة تسميته لاحقاً).
3. ارفع **محتويات المجلد** وليس الملف ZIP نفسه: ملف `package.json` ومجلدا `src` و`scripts` وباقي الملفات، باستعمال `Add file` → `Upload files` أو رابط `uploading an existing file` إن كان المستودع فارغاً.
4. اضغط `Commit changes` على الفرع `main` إن وجد. لا ترفع `.env` الحقيقي أو أي رمز سرّي.
5. بما أنك سبق وربطت GitHub بـ Vercel، افتح Vercel وتحقق هل أنشئ مشروع مرتبط بهذا المستودع. إن لم يوجد: `Add New` → `Project` → `Import` → اختر المستودع. `Framework Preset: Next.js`, `Root Directory: ./`.
6. بعد نجاح النشر انسخ عنوان النشر **الفعلي** المعروض في Vercel. جرّب `<actual-url>/api/health` من المتصفح. يجب أن تظهر `ok:true` و `phase:phase-1-starter`.
7. نقطة MCP ستكون `<actual-url>/mcp` فقط بعد نجاح النشر. لا تضع الرابط في ChatGPT كتكامل فعّال للنشر: السيرفر ما زال للقراءة فقط، وإعدادات OAuth لم تُنفذ بعد.

## تطوير محلي (اختياري)
يتطلب Node.js 20.9+:
```
npm install
npm run typecheck
npm run build
npm run dev
```
ثم افتح `http://localhost:3000` و `http://localhost:3000/api/health`.

بعد النشر:
```
npm run smoke -- https://YOUR-ACTUAL-VERCEL-URL
```
هذا الاختبار يفحص `/api/health` فقط. **اختبار `tools/list` و `tools/call` عبر عميل MCP ضروري قبل اعتبار بروتوكول MCP مجرّبًا**.

## خطوات التطوير القادمة
1. ربط Turso وإنشاء جداول: ideas/tasks/assets/approvals/publish_log/key_metadata.
2. تأمين الواجهة عبر هوية المستخدم و OAuth صحيح لخادم MCP. لا تكفي مجرد كلمة سر ثابتة لوحدها لتكامل ChatGPT OAuth.
3. ربط kie.ai مع حدود تكلفة واضحة، وإظهار فشل الرصيد للمشرف بدل تعليق المهمة للأبد.
4. تخزين دائم للوسائط ثم تنفيذ الدمج، لأن روابط الوسائط المؤقتة ليست أرشيفاً دائماً.
5. نظام اقتراح الأفكار → مراجعة بشرية → إنتاج → **موافقة بشرية صريحة** → نشر فقط على الحسابات المصرّح بها.
6. اختبار رسمي لمتطلبات وحصص Instagram/TikTok/YouTube قبل النشر الآلي. ممنوع تجاوز مراجعات المنصات.

## تنبيهات
- **لا تستخدم Vercel Hobby لأي نشاط تجاري أو بغرض الربح**: السياسة الحالية تخصص Hobby للاستخدام الشخصي غير التجاري. اختَر استضافة تسمح بالاستعمال المقصود قبل تحويل المشروع لربح.
- ألغِ أي GitHub token أو مفتاح Kie/Turso سبق أن ظهر في دردشة أو صورة، ثم أنشئ بديله بسرية من لوحة الخدمة.
- هذا الهيكل لا يضمن عدم تكاليف خدمات الإنتاج المستقبلية ولا يشمل نشرًا حقيقيًا بعد.
